# 기록 보기 달력 요약 설계

## 목표

`기록 보기` 화면 상단에 `요약보기`와 `상세보기` 탭을 추가한다. 기존 기록 목록과 상세·수정·삭제 동작은 `상세보기`로 보존하고, 기본 탭인 `요약보기`에서는 월간 달력으로 날짜별 기록 횟수를 확인할 수 있게 한다.

## 범위

### 포함

- `요약보기`와 `상세보기` 세그먼트 탭
- 첫 진입 시 `요약보기` 선택
- 이전 달과 다음 달 이동
- 날짜별 소변·대변 기록 횟수 표시
- 기록이 있는 날짜 선택 시 해당 날짜로 필터된 `상세보기`로 이동
- 날짜 필터 해제 후 전체 상세 기록으로 복귀
- 기존 상세·수정·삭제 흐름 유지

### 제외

- 주간 또는 연간 통계
- 기록 추세 분석과 의학적 판단
- 검색과 복합 필터
- 달력 아래에 별도 기록 목록 중복 표시
- 기록 작성 기능 변경

## 검토한 표현 방식

1. 기록 유무만 점으로 표시
   - 화면은 단정하지만 하루 기록 횟수를 알 수 없다.
2. 소변·대변 횟수를 각각 표시
   - 월간 패턴과 기록 종류를 함께 읽을 수 있다.
   - 이 방식을 채택한다.
3. 하루 전체 기록 횟수만 표시
   - 숫자는 잘 보이지만 소변과 대변이 섞여 제품의 핵심 구분이 사라진다.

## 화면 구조

기존 헤더 아래에 `요약보기 / 상세보기` 세그먼트 탭을 둔다.

### 요약보기

- 현재 연월과 이전·다음 달 버튼을 표시한다.
- 달력은 일요일부터 토요일까지 7열로 구성한다.
- 날짜 칸에는 해당 날짜의 `소변 N`, `대변 N`을 각각 표시한다.
- `both` 기록은 소변 횟수와 대변 횟수에 각각 1회로 집계한다.
- 오늘 날짜와 사용자가 선택할 수 있는 날짜를 시각적으로 구분한다.
- 기록이 없는 날짜도 빈 날짜 칸으로 유지해 월 전체 구조를 보존한다.
- 기록이 없는 날짜는 상세보기 이동 대상으로 만들지 않는다.

### 상세보기

- 사용자가 탭을 직접 누르면 현재의 전체 기록 목록을 그대로 보여준다.
- 달력에서 날짜를 선택해 이동하면 해당 날짜 기록만 보여준다.
- 날짜 필터가 적용된 경우 목록 위에 `7월 8일 기록`과 `전체 보기` 동작을 표시한다.
- `전체 보기`를 누르면 날짜 필터를 해제하고 기존 전체 목록으로 돌아간다.
- 기록 항목을 누른 뒤 사용하는 상세·수정·삭제 모달은 현재 동작을 유지한다.

## 데이터 조회

전체 상세 목록은 기존 `최근 50개` 조회를 유지한다.

달력 데이터는 표시 중인 달의 로컬 시간 기준 시작 시각 이상, 다음 달 시작 시각 미만 범위로 조회한다. 최근 50개만으로 월간 달력을 만들면 기록이 많은 달의 앞부분이 누락될 수 있으므로 월 범위 조회를 별도로 사용한다.

사용자가 달을 이동하면 해당 월 데이터를 조회한다. 이미 조회한 월로 돌아오면 같은 화면 세션 안에서 받은 데이터를 재사용한다. 저장·수정·삭제로 현재 월의 집계가 달라지면 해당 월 캐시와 화면 상태를 함께 갱신한다.

날짜 집계, 월 달력 칸 생성, 날짜 범위 계산은 `records` route 전용 순수 유틸로 둔다. Supabase 조회 wrapper는 기존 `src/api/bathroomLogs/` 경계에 추가한다.

## 상태와 오류 처리

- 첫 요약보기 로딩은 달력 영역에 로딩 문구를 표시한다.
- 월 조회 실패는 달력 영역에만 오류를 표시하며 상세보기 전체 목록은 계속 사용할 수 있게 한다.
- 기록이 없는 달은 별도 대형 빈 상태 없이 빈 달력을 표시한다.
- 날짜 필터 결과가 비어 있으면 `이 날짜에는 기록이 없습니다.`를 표시한다.
- 상세 목록 조회 실패, 수정 실패, 삭제 실패 문구는 기존 동작을 유지한다.

## 접근성

- 상단 전환 UI는 탭과 탭 패널 관계를 보조 기술이 이해할 수 있게 표현한다.
- 이전·다음 달 버튼에는 대상 동작이 드러나는 접근 가능한 이름을 제공한다.
- 기록이 있는 날짜 버튼의 이름에는 날짜와 소변·대변 횟수를 포함한다.
- 색상만으로 기록 종류나 선택 상태를 구분하지 않고 텍스트를 함께 표시한다.

## 파일 경계

- `RecordsPageClient.tsx`: 탭, 선택 월, 선택 날짜, 조회 상태 조립
- `records` route의 `_component/`: 달력과 탭별 화면처럼 독립적인 route 전용 UI
- `records` route의 `_util/`: 월 범위, 달력 칸, 날짜별 집계와 필터
- `src/api/bathroomLogs/`: 월 범위 기록 조회 wrapper
- 기존 상세·수정 모달: 동작 변경 없이 재사용

새 공용 컴포넌트나 범용 달력 추상화는 만들지 않는다. 현재 사용처가 `records` route 하나이므로 route 전용 구현이 가장 단순하다.

## 검증

- 기본 탭이 `요약보기`인지 확인한다.
- 사용자가 상세보기 탭을 직접 선택하면 기존 전체 목록이 표시되는지 확인한다.
- 소변, 대변, `both` 기록의 날짜별 집계가 정확한지 단위 테스트한다.
- 이전·다음 달 이동 시 올바른 월 범위로 조회하는지 확인한다.
- 기록이 있는 날짜 선택 시 상세보기로 전환되고 해당 날짜만 표시되는지 확인한다.
- `전체 보기`로 날짜 필터가 해제되는지 확인한다.
- 상세·수정·삭제 기존 테스트가 계속 통과하는지 확인한다.
- `npm run typecheck`와 관련 Vitest 테스트를 실행한다.

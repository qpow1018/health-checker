# 기록 화면 UI 정리 설계

## 요약

`RecordPageClient`의 기본 흐름은 유지한다. 화면은 A 목업 방향처럼 차분한 상단 제목 구조를 쓰고, 빠른 기록 버튼은 불필요한 설명을 줄여 반복 사용에 더 맞게 정리한다.

## 목표

- 상단 제목이 화면의 역할을 자연스럽게 설명하게 한다.
- 빠른 기록 버튼이 지나치게 크거나 장황해 보이지 않게 한다.
- 원탭 기록 속도와 터치 안정성은 유지한다.
- 화면이 비어 보인다는 이유로 새 건강 지표나 요약 정보를 추가하지 않는다.

## 선택한 방향

상단은 다음 구조를 사용한다.

- 작은 맥락 라벨: `오늘 기록`
- 제목: `방금 다녀온 기록을 남겨요`
- 보조 문구: `저장 후 필요한 내용만 이어서 적을 수 있습니다.`

빠른 기록 버튼은 세로로 쌓는다. 기존처럼 `소변`, `대변`, `둘 다`의 세 가지 선택지를 유지하되, 버튼 안에 긴 설명 문장을 넣지 않는다.

버튼 안에는 기본 라벨만 둔다.

- `소변`
- `대변`
- `둘 다`

버튼 밖에는 `탭하면 지금 시각으로 바로 저장됩니다.`라는 한 줄 안내만 둔다.

## 제외 범위

- 최근 기록, 일별 요약, 빈 상태 카드 같은 새 정보 영역을 추가하지 않는다.
- `정상`, `비정상`처럼 의학적 판단으로 읽힐 수 있는 문구를 추가하지 않는다.
- 저장 흐름, 상세 입력 바텀시트, 취소 동작은 변경하지 않는다.
- 공용 하단 탭이나 바텀시트 컴포넌트는 변경하지 않는다.

## 구현 범위

- `src/app/(app)/record/RecordPageClient.tsx`
  - 상단 제목 문구를 A 방향으로 조정한다.
  - 빠른 기록 버튼 내부 문구 구조를 짧게 만든다.
- `src/app/(app)/record/recordPageClient.module.scss`
  - 상단 제목 간격과 크기를 정리한다.
  - 버튼 높이와 내부 정렬을 조정한다.
  - 안내 문구는 버튼 밖의 단일 문장으로 유지한다.

## 검증

- 빠른 기록 버튼 `소변`, `대변`, `둘 다`가 계속 렌더링된다.
- 버튼의 기존 클릭 동작과 저장 후 바텀시트 흐름이 유지된다.
- TypeScript 변경 후 `npm run typecheck`를 실행한다.
- React UI 변경이므로 `RecordPageClient` 관련 테스트를 실행한다.

# 기록/기록 보기 UI 정렬 디자인

## 배경

공용 컴포넌트와 기록 화면은 `var(--surface-muted)`, `var(--primary)`, `var(--muted)`, `var(--radius)` 같은 앱 토큰을 기준으로 보이지만, 기록 보기 화면은 별도 베이지 팔레트와 직접 지정한 간격/제목 크기를 사용해 다른 제품처럼 보인다.

## 확정 방향

기록 화면의 강한 빠른 기록 CTA는 유지하고, 기록 보기 화면은 같은 앱 토큰을 쓰는 차분한 정보 화면으로 정리한다.

- 기록 화면은 빠른 저장 행동이 중심이므로 큰 컬러 버튼을 유지한다.
- 기록 보기 화면은 읽기, 확인, 수정이 중심이므로 흰 surface와 얇은 line, 작은 메타 정보 위계로 정리한다.
- 두 화면 모두 같은 앱 캔버스, safe area padding, 헤더 위계, 상태 메시지 스타일을 공유하는 것처럼 보이게 한다.

## 범위

1. `src/app/(app)/records/recordsPageClient.module.scss`에서 별도 색상값을 앱 토큰으로 교체한다.
2. 기록 보기 화면의 헤더 크기와 간격을 기록 화면에 맞춘다.
3. 기록 목록 아이템은 `var(--surface)`, `var(--line)`, `var(--muted)`, `var(--primary)`를 사용해 공용 컴포넌트와 같은 톤으로 정리한다.
4. 첫 구현은 기록 보기 화면의 CSS 정렬로 제한한다. 공용 추출은 동일한 스타일 블록이 두 화면에서 실제로 반복되고, 추출해도 API가 단순할 때 별도 후속 작업으로 진행한다.

## 제외 범위

- 기록 화면의 빠른 기록 플로우나 버튼 구조는 바꾸지 않는다.
- 기록 목록의 데이터 로딩, 편집, 삭제 동작은 바꾸지 않는다.
- 새 장기 디자인 시스템이나 대형 theme layer를 만들지 않는다.
- 하단 탭, 모달, 공용 버튼 API는 현재 구조를 유지한다.

## 컴포넌트 기준

- `BottomNavigation`, `BottomModal`, `Button`, `ConfirmModal`은 이미 공용 컴포넌트로 사용한다.
- 기록 보기 화면의 route-local 리스트/빈 상태 UI는 `src/app/(app)/records` 안에서 유지한다.
- 공용 추출은 동일한 스타일 블록이 기록 화면과 기록 보기 화면에 실제로 중복될 때만 작게 진행한다.

## 검증

- TypeScript 동작 변경이 없더라도 React/SCSS 변경 후 `npm run typecheck`를 실행한다.
- 기존 기록 보기 테스트가 UI 텍스트나 접근성 역할에 의존하므로 관련 테스트를 실행한다.
- 브라우저 또는 WebView 폭 기준으로 헤더, 상태 메시지, 리스트 항목의 줄바꿈과 하단 탭 겹침을 확인한다.

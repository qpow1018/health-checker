# 기록 화면 설계

## 요약

`record`는 모바일 앱의 기본 첫 화면이다. 웹 페이지 안의 카드처럼 보이기보다 앱 화면 자체처럼 보여야 한다. 화면은 원탭 기록 속도를 유지하고, 저장 후 필요한 후속 행동을 화면 아래에서 제공한다.

선택한 상호작용 모델은 다음과 같다.

1. 사용자가 `소변`, `대변`, `둘 다` 중 하나를 누른다.
2. 앱은 현재 시각으로 기록을 저장한다.
3. 저장된 기록 요약을 담은 바텀시트가 열린다.
4. 사용자는 상세를 추가하거나, 방금 만든 기록을 취소하거나, 바텀시트를 닫을 수 있다.

## 목표

- 앱을 열자마자 가장 중요한 기록 행동에 바로 도달하게 한다.
- 저장 전 확인 단계를 두지 않아 원탭 기록 속도를 유지한다.
- 잘못 눌렀을 때 저장 직후 바로 되돌릴 수 있게 한다.
- 상세 입력은 선택 사항이자 두 번째 단계로 둔다.
- 고정 하단 탭을 사용하는 모바일 WebView 방향과 맞춘다.
- 기록 화면에는 가운데 카드나 대시보드 카드형 레이아웃을 쓰지 않는다.

## 제외 범위

- 화장실 기록을 넘어서는 범용 건강 추적 기능을 추가하지 않는다.
- `정상`, `비정상` 같은 의학적 판단 표현을 추가하지 않는다.
- 첫 기록 화면 구현에 일별 요약을 넣지 않는다.
- `record` 화면이 전체 기록 목록까지 책임지게 하지 않는다.
- 회원가입, 온보딩, 공개 계정 흐름을 추가하지 않는다.

## 레이아웃

화면은 전체 모바일 앱 캔버스로 구성한다.

- 상단 영역: `오늘 기록` 같은 짧은 화면 맥락.
- 본문 영역: `소변`, `대변`, `둘 다`에 대한 큰 세로 액션 버튼.
- 하단 영역: `기록`, `기록 보기`, `AI 리포트`, `설정` 고정 탭.
- 기록 화면 본문에는 가운데 정렬된 `.surface` 카드를 사용하지 않는다.

주요 액션 버튼은 세로로 쌓는다. 이렇게 하면 터치 영역을 크게 유지할 수 있고, 좁은 모바일 화면에서도 한국어 라벨이 안정적으로 들어간다.

## 기록 흐름

빠른 기록 버튼은 현재 시각으로 기록을 만든다.

지원하는 기록 종류는 다음과 같다.

- `urine`: `소변`
- `bowel`: `대변`
- `both`: `둘 다`

저장이 성공하면 바텀시트를 연다. 바텀시트에는 다음을 표시한다.

- `방금 저장됨`
- 기록 종류 라벨
- 저장 시각
- `상세 추가`
- `취소`
- `닫기`

`상세 추가`는 저장된 기록의 상세 입력 상태를 연다. 상세 입력은 빠른 저장보다 뒤에 있는 보조 단계이며, 기록이 먼저 만들어진 뒤에만 진입한다.

상세 입력에는 다음 항목을 포함한다.

- 공통 항목: 긴급도, 자다가 깼음, 메모.
- `urine`과 `both`에서 쓰는 소변 항목: 통증, 색이 평소와 다름.
- `bowel`과 `both`에서 쓰는 대변 항목: 상태, 통증, 혈변 의심.

상세 저장은 방금 만든 기록을 업데이트하고 상세 입력 상태를 닫는다.

`닫기`는 저장된 기록을 그대로 두고 바텀시트만 닫는다.

## 잘못 누른 경우

기록 화면은 마지막으로 방금 만든 기록에 대한 즉시 취소를 지원한다.

규칙은 다음과 같다.

- 저장 전 확인 모달은 두지 않는다.
- `취소`는 저장 후 바텀시트에서만 보여준다.
- `취소`는 현재 바텀시트가 가리키는 기록 하나에만 적용한다.
- 바텀시트를 닫았거나 다른 기록을 만든 뒤의 이전 기록은 `기록 보기`에서 수정하거나 삭제한다.
- 취소가 성공하면 바텀시트를 닫고 기본 빠른 기록 상태로 돌아간다.
- 취소가 실패하면 바텀시트를 유지하고, 의학적 안내가 아닌 일반 오류 문구를 보여준다.

이 방식은 기록 속도를 유지하면서도 실수 입력을 되돌릴 수 있게 한다.

## 데이터 경계

`bathroom_logs`가 기록 데이터의 source of truth다.

기록 화면은 건강 기록을 WebView localStorage에 저장하지 않는다. 브라우저나 클라이언트 상태에는 현재 표시 중인 방금 저장된 기록처럼 일시적인 UI 상태만 둔다.

구현은 기록 화면 전용 UI 상태 타입을 route-local 위치에 둔다. 첫 구현에서 실제 저장을 연결한다면, 여러 화면에서 재사용할 Supabase wrapper는 `src/api/`에 둔다.

## 오류 상태

오류 문구는 명확한 한국어 UI 상태로 표현하고, 의학적 안내처럼 쓰지 않는다.

저장 실패:

- 사용자를 기록 화면에 그대로 둔다.
- 기록이 저장되지 않았음을 보여준다.
- 다시 시도할 수 있게 한다.

취소 실패:

- 바텀시트를 열린 상태로 둔다.
- 취소가 완료되지 않았음을 보여준다.
- 삭제가 실제로 성공하지 않았다면 건강 기록이 제거됐다고 암시하지 않는다.

인증과 allowlist 실패는 `AuthGate`의 책임으로 유지한다.

## 검증

기록 화면 테스트는 다음을 확인해야 한다.

- 빠른 기록 버튼 `소변`, `대변`, `둘 다`가 렌더링된다.
- 주요 기록 UI가 가운데 카드형 surface에 의존하지 않는다.
- 빠른 기록 액션을 누르면 방금 저장된 기록의 바텀시트가 열린다.
- 바텀시트에는 `상세 추가`, `취소`, `닫기`가 있다.
- `상세 추가`를 누르면 저장된 기록 종류에 맞는 상세 필드가 열린다.
- `닫기`는 기록을 취소하지 않고 바텀시트만 닫는다.
- `취소`는 현재 방금 저장된 기록에 대한 취소 경로를 호출한다.
- 로그아웃을 기록 화면에 유지한다면, 로그아웃 동작도 계속 가능해야 한다.

TypeScript 또는 React 변경 후에는 `npm run typecheck`와 관련 테스트를 실행한다.
